# Portal regression review — 2026-10-31

## Change

Individual extracted-field Edit buttons are now pencil icons placed inside the leading edge of each value control. A checkmark finishes individual editing. Accessible names and tooltips remain; Edit all, field/source selection, text areas, checkbox selections and draft/save behavior are preserved. Lucide pencil/check assets are explicitly allowed by the server. No extraction rules or database schema changed.

## Issues found and resolved

Visual inspection found the pencil absent because the server icon allowlist lacked the two new files. Added both paths, restarted the server, and strengthened browser checks to require successfully decoded images. Retested placement, source controls and live endpoints.

The new Excel validation initially expected null for a cleared address. ExcelJS reads the exported explicit empty string as an empty string; the test now asserts that exact blank value. Both generated workbooks passed; no export code was changed.

Tests used the isolated PostgreSQL QA environment, not live accounts/documents. Shared-session logout tests ran after other browser checks to prevent session-revocation interference. Existing QA records were retained; no production data was deleted. No unresolved failures remain in the executed checks.

## Scope and limitations

This is functional regression testing of the implemented workflows and supported sample, not proof for every browser, possible PDF or concurrent-user scenario. The previous five-fixture/302-assertion extraction campaign was not repeated because OCR code was unchanged; extraction unit checks and the full four-page upload/edit/export workflow were rerun for both roles. Type checking remains scoped to the existing new-backend configuration. Browser-level close/refresh/history controls cannot display portal-owned confirmation dialogs; internal navigation does protect unsaved changes.
